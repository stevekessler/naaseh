# Native profile and web administration boundary

The native apps support only self-service settings for the signed-in person: display name, email,
time zone, device-local alert/sound/private-preview preferences, password changes, two-factor
enrollment and verification, remembered-device removal, and session
revocation. Security and integration mutations require an online validated session and clearly say
whether a change was saved, unchanged, or left unsaved.

The native apps do not include routes, binaries, menus, or mutations for user administration,
provisioning, role changes, group administration, project/category creation or lifecycle,
operator recovery, backup/restore operation, AWS management, or audit administration. Those remain
in the existing web interface. An administrator who signs in to a native app receives the same
personal feature set and data authorization as any other account; the role does not enable hidden
native screens or expand access to Journal, Crisis Plan, private task, attachment, or recovery data.

Use the web app for project/category management and every administrative or operator workflow.
