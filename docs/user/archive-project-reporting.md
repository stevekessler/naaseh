# Archive, Projects, and Completed Tasks

Completing a to-do automatically moves it to **Archive** and records one completion. Use
**Archive without completing** when the work should disappear from active views without receiving
credit. Finishing a List archives the List as a unit; its Items stay with it. Authorized group and
private access rules do not change in Archive. Restore reopens work and reverses completion credit
when appropriate.

Administrators organize work in exactly two levels: **Category → Project**. Project names need to
be unique only inside their Category, so both `PAAO → API` and `Another Category → API` are valid.
Assign a to-do or List to a Project, or choose Unassigned. Category is derived from the Project.
The Projects page rolls Project counts up to each Category and shows separate to-do/List counts,
end dates, overdue state, and exact drill-down links.

Completed Tasks groups personal to-do completions by day, week, or month in an IANA time zone. Empty
periods are omitted from the chart while totals and exports continue to include the full report.
Filters include Unassigned, Category, and Project; archived organization labels remain available
because reports use the names captured at completion time. Pending offline changes are identified.

Categories and Projects remain editable after archive. An archived Category makes all its Projects
unavailable for new assignments without changing the Projects’ own lifecycle. Restore reverses
that effective block. Permanent deletion is online-only, requires a warning and confirmation, and
is allowed only when no child, work, history, projection, or pending-job reference remains. It is
irreversible and has no recycle bin.

Trees, dialogs, filters, and charts use semantic labels, keyboard-operable controls, visible focus,
text status in addition to color, touch-sized actions, and responsive layouts without horizontal
overflow. Reduced-motion preferences continue to apply to completion feedback.
