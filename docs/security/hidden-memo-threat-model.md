# Hidden memo threat model

Hidden memo plaintext exists only in browser memory after unlock. AES-256-GCM uses a random per-memo data key and canonical task/memo/version AAD. The data key is wrapped independently for offline PIN unlock and for two signed AWS recovery keys. PIN derivation uses Argon2id in a worker with 100 MiB, three iterations, and parallelism one; copied browser storage still permits offline guessing, so users need strong PINs. Search tokens for unlocked plaintext remain in memory and purge on lock, tab hiding, or inactivity. Routine API roles cannot decrypt. Owner recovery requires password re-verification and an isolated, audited KMS recovery role. Logs, backups, analytics, errors, and revision metadata never contain plaintext, PINs, raw keys, or hidden search terms.
