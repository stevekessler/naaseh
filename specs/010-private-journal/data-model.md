# Data Model: Private Journal and Wellness Dashboard

## Boundary conventions

- `ownerId`, opaque record IDs, opaque date tokens, entity/key/schema versions, ciphertext byte size, and operational timestamps are the only server-readable journal routing fields.
- Local journal dates, answers, DBT selections, notes, task IDs, preferences, dashboard values, and contributing-entry sets exist only inside authenticated ciphertext or unlocked browser memory.
- Every durable journal ciphertext uses AES-256-GCM with a fresh 96-bit IV and canonical AAD binding `ownerId`, opaque record ID, record kind, schema version, key version, and date token when applicable.
- A single server transaction commits the projection, body, date pointer, mutation receipt, and feed change for an entry version. The projection and body never advance independently.
- Journal entities support create and update only. No user, administrator, recovery, tombstone, export, or purge state exists.

## Cryptographic entities

### JournalKeyEnvelope

One versioned key record per owner, readable only by that owner and the isolated recovery workflow.

| Field | Type | Visibility | Rules |
|---|---|---|---|
| `id` | literal `journal-key` | Routing | Stable per owner |
| `ownerId` | opaque user ID | Routing | Must equal authenticated owner |
| `version` | positive integer | Routing | Optimistic concurrency; starts at 1 |
| `keyVersion` | positive integer | Routing | Identifies JMK derivation/AAD generation |
| `ownerWrap.algorithm` | literal `ARGON2ID-AES-256-GCM` | Envelope metadata | Fixed allowlist |
| `ownerWrap.salt` | base64url bytes | Protected envelope | At least 16 random bytes |
| `ownerWrap.parameters` | object | Envelope metadata | Versioned, calibrated Argon2id parameters; current baseline 100 MiB, 3 iterations, parallelism 1 |
| `ownerWrap.iv` | base64url bytes | Protected envelope | Exactly 12 random bytes |
| `ownerWrap.ciphertext` | base64url bytes | Protected envelope | Authenticated JMK wrap; never logged |
| `recoveryWrap.algorithm` | literal `RSA-OAEP-256` | Envelope metadata | Fixed allowlist |
| `recoveryWrap.authority` | literal `recovery` | Envelope metadata | No ordinary admin authority |
| `recoveryWrap.keyVersion` | positive integer | Envelope metadata | Must exist in signed recovery-key registry |
| `recoveryWrap.ciphertext` | base64url bytes | Protected envelope | JMK encrypted to recovery public key; never logged |
| `createdAt`, `updatedAt` | UTC timestamps | Operational | Generated by accepted transaction |

The JMK is 256 bits of browser-generated random material. The browser imports unlocked material as a non-extractable HKDF base key and derives keys with domain-separated labels such as `journal:projection:v1:<entryId>`, `journal:body:v1:<entryId>`, `journal:profile:v1`, and `journal:date-identity:v1`.

### CiphertextEnvelope

Reusable wire/storage shape for journal profile, projection, and body ciphertext.

| Field | Type | Rules |
|---|---|---|
| `recordKind` | `profile`, `projection`, or `body` | Must match the endpoint/entity type and AAD |
| `schemaVersion` | positive integer | Reject unsupported future versions without overwriting local data |
| `keyVersion` | positive integer | Must match a known JournalKeyEnvelope version |
| `iv` | base64url bytes | Exactly 12 bytes; unique for the derived record key |
| `ciphertext` | base64url bytes | Includes GCM tag; projection/body each at most 300 KiB encoded request budget |
| `byteSize` | non-negative integer | Must equal decoded ciphertext bytes; used only for request bounds |

Ciphertext, IV, and byte size are never sent to general structured logging even though byte size is routing metadata.

## Owner plaintext entities (encrypted at rest)

### JournalProfile

One decrypted profile per owner, stored as a `CiphertextEnvelope(recordKind=profile)`.

| Field | Type | Rules |
|---|---|---|
| `schemaVersion` | literal `1` | Versioned migration boundary |
| `ownerId` | user ID | Must match authenticated/unlocking owner and AAD |
| `suicidalSelfHarmEnabled` | boolean | Defaults to `true` when profile absent |
| `dbtSkillsEnabled` | boolean | Defaults to `true` when profile absent |

Disabling a section never edits historical JournalEntryProjection ciphertext. It only changes owner-side presentation and dashboard inclusion.

### JournalEntryProjection

Compact decrypted record used for list ordering, date filtering, dashboard calculation, and entry-form structured values.

| Field | Type | Rules |
|---|---|---|
| `schemaVersion` | literal `1` | Strict schema |
| `id` | UUID | Stable through date changes and edits; must match envelope/AAD |
| `ownerId` | user ID | Must match active owner |
| `date` | local date `YYYY-MM-DD` | Required; no future conversion through UTC |
| `suicidalThoughts` | integer or null | 1–10 |
| `suicidalBehaviors` | boolean or null | Optional yes/no |
| `selfHarmThoughts` | integer or null | 1–10 |
| `selfHarmBehaviors` | boolean or null | Optional yes/no |
| `alcoholicDrinks` | integer or null | 1–10 |
| `otherDrugs` | boolean or null | Optional yes/no |
| `medicationsAsPrescribed` | boolean or null | Optional yes/no |
| `hoursOfSleep` | number or null | 1–24 in 0.5 increments |
| `urgeToAvoidCommitments` | integer or null | 1–100 |
| `conflictWithOthers` | boolean or null | Optional yes/no |
| `balancedEating` | boolean or null | Optional yes/no |
| `selfCare` | boolean or null | Optional yes/no |
| `emotions` | object | Each of anger, fear, anxiety, pain, sadness, shame, guilt, loneliness, joy, contentment is integer 1–100 or null |
| `dbt` | DbtSkillsResponse or null | Entire group optional |
| `createdAt`, `updatedAt` | UTC timestamps | Encrypted content; used for owner display/conflict context only |

Every response other than `date` is nullable. `null` is never coerced to `0` or `false`.

### DbtSkillsResponse

| Field | Type | Rules |
|---|---|---|
| `practiceOutcome` | enum or null | One of the seven spec-defined phrases |
| `mindfulness` | enum array | Unique subset of the eight defined skills |
| `emotionRegulation` | enum array | Unique subset of the ten defined skills |
| `interpersonalEffectiveness` | enum array | Unique subset of the five defined skills |
| `distressTolerance` | enum array | Unique subset of the eleven defined skills |

Empty arrays mean answered with no selected skills only when the UI explicitly represents that state; an entirely unanswered group may be `null`.

### JournalEntryBody

Decrypted only for the single-entry page.

| Field | Type | Rules |
|---|---|---|
| `schemaVersion` | literal `1` | Strict schema |
| `entryId` | UUID | Must match projection and AAD |
| `generalNotes` | JournalDocument or null | Optional; no product character limit; bounded only by safe processing/envelope size |
| `taskReflection` | TaskReflection or null | Optional |

### TaskReflection

| Field | Type | Rules |
|---|---|---|
| `taskId` | opaque task ID | Selected from currently authorized eligible local tasks; remains encrypted |
| `notes` | JournalDocument or null | Optional rich text |

The journal association grants no task permission. On display, the task ID is resolved against current authorized task data. Missing/inaccessible tasks render “Task unavailable” without a saved title snapshot.

### JournalDocument

A structural, versioned rich-text AST; never stored or rendered as raw HTML.

```text
JournalDocument {
  version: 1
  blocks: Paragraph | OrderedList | UnorderedList
}
Paragraph { type: "paragraph", children: TextRun | LinkRun }
OrderedList | UnorderedList { type, items: ListItem[] }
ListItem { children: TextRun | LinkRun }
TextRun { type: "text", text, marks: unique subset[bold, italic, underline, strikethrough] }
LinkRun { type: "link", href: HTTPS URL, children: TextRun[] }
```

- Normalize adjacent equal-mark runs and remove empty runs.
- Permit only absolute `https:` links; render with safe `rel` behavior when opened externally.
- Reject unknown nodes, marks, URL protocols, executable content, and excessive structural depth/count before encryption and after decryption.
- Enforce only infrastructure/safe-processing byte bounds, not a product-defined character maximum. Preserve an oversized encrypted local draft and mark it unsynced.

## Server routing and synchronization entities

### JournalEntryCiphertextRecord

| Field | Type | Rules |
|---|---|---|
| `ownerId` | opaque user ID | Partition owner; authorization source |
| `entryId` | UUID | Opaque stable record ID |
| `dateToken` | base64url HMAC | 256-bit keyed token; never a public date hash |
| `version` | positive integer | Starts at 1; exact conditional increment |
| `projection` | CiphertextEnvelope | `recordKind=projection` |
| `body` | CiphertextEnvelope | `recordKind=body`; same entity version |
| `createdAt`, `updatedAt` | UTC timestamps | Server operational timestamps |

Suggested single-table keys:

```text
PK = JOURNAL#OWNER#<ownerId>
SK = ENTRY#<entryId>
```

### JournalDatePointer

```text
PK = JOURNAL#OWNER#<ownerId>
SK = DATE#<dateToken>
data = { entryId, entityVersion }
```

Pointer creation is conditional on absence. A date edit conditionally creates the new pointer, deletes the old pointer only when it still names this entry/version, and updates the ciphertext entity in one transaction.

### JournalMutation

| Field | Type | Rules |
|---|---|---|
| `id` | UUID/idempotency ID | Unique per logical attempt; duplicates return prior result |
| `entityType` | `journalEntry`, `journalProfile`, or `journalKeyEnvelope` | Version-5 sync allowlist |
| `operation` | literal `upsert` | Delete/tombstone rejected |
| `entityId` | opaque ID | Must match payload identity/AAD metadata |
| `baseVersion` | non-negative integer | `0` for create; exact current version for update |
| `dateToken` | opaque HMAC or absent | Required only for journal entry |
| `priorDateToken` | opaque HMAC or absent | Required only when changing date |
| `payload` | ciphertext envelope(s) | Strictly rejects journal plaintext field names |
| `createdAt` | UTC timestamp | Retry ordering only |

### JournalMutationReceipt and JournalFeedChange

Receipts bind owner, mutation ID, entity type/ID, outcome, and entity version for stable replay. Feed changes contain the accepted ciphertext envelopes and opaque routing metadata, never a tombstone. Owner-only monotonically increasing feed sequence supports paginated pull/bootstrap.

### LocalJournalConflict

Stored only in encrypted IndexedDB.

| Field | Type | Rules |
|---|---|---|
| `id` | UUID | Local conflict ID |
| `entityId` | opaque ID | Entry/profile/key envelope |
| `baseVersion`, `remoteVersion` | integers | Conflict context |
| `localCiphertext`, `remoteCiphertext` | encrypted envelopes | Both retained until explicit resolution |
| `kind` | `version` or `date-token` | Drives resolution UI |
| `createdAt` | timestamp | Local operational context |

Resolution transitions `unresolved → choose-local | choose-remote | manual → resolved`. Choosing remote discards only after explicit owner confirmation; choosing local/manual queues a new mutation against `remoteVersion`.

## Recovery entities

### JournalRecoveryRequest

| Field | Type | Rules |
|---|---|---|
| `id` | random opaque ID | Non-enumerable |
| `ownerId` | user ID | Must equal initiating authenticated user |
| `state` | enum | See state machine below |
| `sessionEpochDigest` | digest | Binds request to current owner security state |
| `keyEnvelopeVersion`, `recoveryKeyVersion` | integers | Exact wrap target |
| `ephemeralPublicKeySpki` | base64url | RSA-OAEP, at least 2048 bits; never logged |
| `ephemeralPublicKeyDigest` | digest | Audit binding |
| `reasonDigest` | digest | Reason text is validated transiently and never persisted/logged |
| `ownerApprovedAt`, `adminApprovedAt` | timestamps or null | Strong-auth evidence timestamps |
| `adminApprovalId` | opaque ID or null | Dedicated recovery authorization |
| `expiresAt` | timestamp | Five minutes after creation |
| `consumedAt` | timestamp or null | Exactly once |
| `resultCiphertext` | base64url or null | JMK encrypted only to owner ephemeral key; never returned to admin |

State transitions:

```text
requested
  ├─ owner_cancelled
  ├─ expired
  └─ admin_approved
       ├─ denied/expired
       └─ rewrapped
            └─ consumed
                 └─ completed (replacement owner wrap committed; sessions advanced)
```

Every transition uses conditional state/version checks. Reuse, mismatch, stale session epoch, missing recent owner password verification, missing fresh administrator password+TFA, or wrong public-key/key-envelope binding fails closed.

### JournalRecoveryAuditEvent

Append-only event containing audit/request/approval IDs, opaque actor/owner IDs, state transition/outcome, reason digest, session/public-key fingerprints, recovery-key version, correlation ID, elapsed time, timestamp, previous-event hash, and current-event hash. Terminal chain heads are signed by the existing manifest-signing KMS key. No content, date, field name/value, note, task ID, ciphertext, wrap, IV, salt, key, public key, or reason text is allowed.

## Ephemeral dashboard models

### DashboardPeriod

| Field | Type | Rules |
|---|---|---|
| `start`, `end` | local dates | Inclusive; `start <= end` |
| `comparisonStart`, `comparisonEnd` | local dates | Immediately preceding, non-overlapping, equal number of calendar days |

### DashboardMetric

| Field | Type | Rules |
|---|---|---|
| `metric` | dashboard metric enum | Exactly the requested cards; sensitive four conditional on profile |
| `kind` | `dayCount`, `yesDayCount`, or `average` | Determines label/aggregation |
| `value` | number or `noData` | Missing answers excluded; no data differs from zero/no |
| `comparisonValue` | number or `noData` | Prior equal period |
| `trend` | `up`, `down`, `unchanged`, or `notComparable` | Numeric direction only, never clinical meaning |
| `contributingEntryIds` | UUID array | Entries with an answered contributing value; owner memory only |

Dashboard metrics are derived and held in unlocked memory. If cached for responsiveness, the entire cache must use a JMK-derived encryption key and be invalidated by any contributing projection/profile version change.

## Local IndexedDB schema version 12

Add stores without exposing date, answers, task association, or values as indexes:

```text
secureJournalKeyEnvelope: id, ownerId, version, updatedAt
secureJournalProfiles: id, ownerId, version, updatedAt
secureJournalEntries: id, ownerId, version, updatedAt, dateToken
secureJournalBodies: id, ownerId, version, updatedAt
secureJournalConflicts: id, ownerId, entityId, createdAt
```

Values in every store are ciphertext. `dateToken` is opaque. Existing `outbox` carries an additional `journalEntry|journalProfile|journalKeyEnvelope` entity type, with its payload protected by the persisted device key outside a journal session and containing only JMK ciphertext envelopes internally. Migration is additive and resumable; it preserves all existing stores/outbox/conflicts and validates that no journal plaintext fields appear in records.

## Cross-entity invariants

1. One owner has one active JournalKeyEnvelope and one JournalProfile.
2. One owner/date token points to exactly one stable entry ID.
3. Projection, body, date pointer, receipt, and feed entity version advance atomically.
4. Decrypted `ownerId`, entry ID, record kind, key/schema version, and date token must match AAD/routing metadata before any value is rendered.
5. A disabled section changes visibility only; it does not rewrite or erase historical projection data.
6. A task reference is private content and never grants or preserves task authorization.
7. Journal records have no delete or export transition.
8. Recovery never changes journal ciphertext or exposes the JMK to the administrator; it only replaces the owner wrap after the owner browser receives the one-use rewrap.
9. Dashboard calculations use only decrypted projections whose dates fall inclusively within the selected or comparison period, and exclude null values from denominators/contributor sets.
